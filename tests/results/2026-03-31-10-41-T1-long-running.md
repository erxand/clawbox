## ISSUE-53 discovered (fixed this session)
**Root cause of false SKIP:** `is_rate_limited()` in `tests/lib/common.sh` included `"529"` as a bare pattern. The task description contained `taskman-1774975299` — this number includes `529` as a substring, causing `grep -qi "529"` to match the task log header. After the full 20-minute poll, T1 read the task log looking for rate-limit signals and false-positive matched the project directory name, SKIPping a fully successful run.
**Fix applied:** Removed `"529"` from `RATE_LIMIT_PATTERNS`. HTTP 529 (Overloaded) is already covered by the more specific `"overloaded_error"` pattern emitted by the Anthropic API and detected by `clawbox run`'s `CLAWBOX_RATE_LIMITED` sentinel.

## ISSUE-54 discovered (fixed this session)
**Problem:** T1's early-exit loop ran the full 20-minute timeout even though the agent completed in ~6 minutes. The early-exit grep looks for `Status: COMPLETE` in TASK.md, but this agent used phase checkboxes (`Phase N: ✅` for all phases) as its completion signal. The `Status: COMPLETE` pattern never fired.
**Fix applied:** T1 now also counts `Phase N: ✅` lines vs total `### Phase N:` headers. When `phases_done == phases_total` (and total > 0), the poll loop exits early. This should save 10-14 minutes per run on successful completions.
